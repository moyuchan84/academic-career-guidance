정보 · 중학교 단원 지도

중학교에서 정보가 독립 교과로 시작돼요. 5개 영역(컴퓨팅 시스템, 데이터, 알고리즘과 프로그래밍, 인공지능, 디지털 문화)의 대표 단원을 핵심 개념과 확인 질문으로 정리했어요. 부모 역할은 가르치기가 아니라 설명시키기, 프로젝트 지원, 스크린 균형이에요. 파이썬을 몰라도 이 페이지의 질문만으로 충분히 도울 수 있어요.

“엄마한테 설명해 줄래?”로 확인 질문을 던져요. 답은 ‘답 보기’에 있어요.

영역별 단원 지도

중학교 정보는 학년군(중1~3)으로 묶여 있어 학년이 아닌 영역으로 탭을 나눴어요. 대부분의 교과서가 컴퓨팅 시스템·데이터로 시작해 알고리즘과 프로그래밍에 가장 많은 시간을 쓰고, 인공지능·디지털 문화로 마무리하지만 순서는 다를 수 있어요.

컴퓨터가 “어떻게 생겼고 어떻게 서로 연결되는지”를 배우는 영역이에요. 하드웨어·소프트웨어·운영체제의 역할, 네트워크, 센서를 쓰는 피지컬 컴퓨팅이 대표 내용이에요.

컴퓨팅 기기의 구성과 동작하드웨어·소프트웨어·운영체제의 역할

핵심 개념

  • 하드웨어: 입력·출력 장치, 처리 장치(CPU), 기억 장치(주기억 메모리 = 작업대, 보조기억 저장장치 = 서랍).
  • 소프트웨어: 운영체제(기기 전체 관리, 자원 배분)와 응용 소프트웨어(앱).
  • 프로그램은 저장장치에 있다가 실행할 때 메모리로 올라와 CPU가 명령을 하나씩 처리해요.

부모 역할 · 이렇게 도와요

  1. “폰 저장공간은 넉넉한데 왜 앱을 많이 켜면 느려질까?” 질문으로 메모리와 저장장치 차이를 설명하게 해요.
  2. 집 컴퓨터 사양(설정 → 시스템 정보)을 아이가 읽어 주게 해요.
  3. “운영체제가 없으면 어떤 일이 벌어질까?” 상상 설명 듣기.

확인 질문
  1. 전원을 끄면 내용이 사라지는 기억 장치는?
    답 보기

    주기억 장치(RAM)예요. 저장장치(SSD 등)는 전원이 꺼져도 남아요.

  2. 운영체제가 하는 일 두 가지는?
    답 보기

    예: 하드웨어 자원(CPU·메모리) 관리, 파일 관리, 사용자와 기기 연결(화면·입력).

  3. 프로그램을 실행하면 어디에서 어디로 옮겨질까?
    답 보기

    저장장치에서 주기억 장치로 올라와 CPU가 처리해요.

연결

초5 실과 컴퓨터와 소프트웨어(초등 단원 지도) → 이 단원 → 고등 정보 컴퓨팅 시스템.

부모가 먼저 알아 둘 것

교과서는 컴퓨터를 입력 → 처리(CPU) → 출력과 기억(주기억·보조기억)으로 나눠요. 주기억 장치(RAM)는 CPU가 지금 쓰는 자료를 올려 두는 “작업대”라 빠르지만 전원이 꺼지면 지워지고, 보조기억 장치(SSD·HDD·USB)는 “서랍”이라 느리지만 전원이 꺼져도 남아요. 앱을 많이 켜면 느려지는 건 작업대(RAM)가 꽉 차기 때문이에요. 운영체제(윈도우, 안드로이드, iOS 등)는 CPU 시간·메모리·파일·입출력 장치를 나눠 주는 관리자예요. 부모가 컴퓨터를 잘 몰라도 괜찮아요. 오늘은 아이가 선생님, 부모는 질문하는 학생이에요.

오늘의 목표 (아이에게 이렇게)

“우리 집 컴퓨터가 어떻게 일하는지 엄마한테 설명해 줄 수 있으면 성공!”

준비물

집 컴퓨터나 휴대폰(설정·작업 관리자 화면), 종이, 책상과 서랍

시간

회당 15분 × 3회

  1. 만나기 — 경험에서 시작

    부모“폰 저장공간은 아직 많이 남았는데, 앱을 여러 개 켜면 왜 버벅일까?”

    아이 예상“용량이 꽉 차서?”

    바로 정답을 말하지 말고 설정 화면에서 “저장공간 128GB”와 “메모리(RAM) 8GB”처럼 숫자가 두 가지라는 걸 같이 찾아봐요. “왜 두 개나 있을까?”를 숙제처럼 남겨요.

  2. 이해하기 — 함께 풀기

    부모“게임 앱을 눌렀을 때 컴퓨터 안에서 무슨 일이 벌어지는지 순서대로 설명해 볼래?”

    함께 풀기

    문제: 저장된 게임 앱을 터치해서 화면에 게임이 뜨기까지의 과정을 장치 이름으로 설명하기

    1. 터치스크린(입력 장치)이 “눌렀다”는 신호를 보내요.
    2. 운영체제가 “이 앱 실행해”를 받아 메모리 자리를 나눠 줘요.
    3. 앱 파일이 보조기억 장치(서랍)에서 주기억 장치(작업대)로 올라와요.
    4. CPU가 메모리에 올라온 명령을 하나씩 처리해요.
    5. 결과가 화면·스피커(출력 장치)로 나와요. 책상과 서랍으로 직접 흉내 내 보면 오래 기억해요.
  3. 해 보기 — 혼자서
    혼자 해 보기
    1. 마이크, 스피커, 프린터, 키보드를 입력·출력 장치로 나눠 보세요.
      답 보기입력: 마이크·키보드 / 출력: 스피커·프린터. 컴퓨터로 들어가면 입력, 나오면 출력이에요.
    2. 터치스크린은 입력일까 출력일까?
      답 보기둘 다예요. 손가락 위치를 받고(입력), 화면을 보여 줘요(출력).
    3. 문서를 쓰다가 저장 전에 정전이 됐어요. 글이 사라진 까닭은?
      답 보기작성 중인 내용은 주기억 장치(RAM)에만 있었기 때문이에요. 저장을 눌러야 보조기억 장치에 남아요.
    4. RAM 4GB 노트북과 8GB 노트북 중 창을 여러 개 켤 때 더 여유 있는 쪽은?
      답 보기8GB예요. 작업대가 넓어 동시에 올려 둘 수 있는 프로그램이 많아요.
    5. 운영체제가 없다면 어떤 일이 생길지 한 가지 말해 보세요.
      답 보기예: 앱마다 메모리·CPU를 서로 차지하려 다투고, 파일을 찾거나 장치를 쓰는 방법을 앱이 전부 따로 만들어야 해요.

네트워크와 인터넷데이터가 어떻게 오가는가

핵심 개념

  • 네트워크는 기기들이 서로 데이터를 주고받도록 연결된 것, 인터넷은 전 세계 네트워크의 네트워크예요.
  • 데이터는 작은 조각(패킷)으로 나뉘어 주소(IP)를 보고 전달되고, 도착해서 다시 합쳐져요.
  • 유선·무선(와이파이) 연결, 공유기의 역할, 공용 와이파이의 보안 위험.

파이썬 ④ 리스트여러 값을 한 이름으로, 인덱스와 반복

핵심 개념

  • 리스트는 여러 값을 순서대로 담아요: scores = [80, 95, 70].
  • 인덱스는 0부터 시작: scores[0]은 80. len()으로 개수, append()로 추가.
  • for s in scores:로 모든 값을 차례로 처리해요(합계·최댓값·개수 세기).

부모 역할 · 이렇게 도와요

  1. 가족 데이터(가족 키, 이번 주 걸음 수)를 리스트로 만들어 평균·최댓값을 구해 달라고 부탁해요.
  2. “첫 번째 값은 몇 번 칸이야?” 0부터 세는 것만 확인.
  3. 결과를 가족 단톡방에 공유하는 즐거움 주기.
steps = [5200, 8100, 6400, 9900] print(max(steps), sum(steps) / len(steps))

  • 장소동네 도서관·청소년수련관의 코딩 교실(방학 프로그램이 많아요) — 청소년 코딩 교실·온라인 실습 과제

부모가 먼저 알아 둘 것

리스트는 여러 값을 번호 붙은 칸에 순서대로 담아요: scores = [80, 95, 70]. 번호(인덱스)는 0부터 시작해서 scores[0]은 80, 마지막 칸은 len(scores) − 1번이에요. 없는 칸을 부르면 IndexError가 나요. append()는 끝에 추가, len()은 개수, sum()·max()는 합계·최댓값이에요. for s in scores: 는 칸의 값을 하나씩 s에 넣어 반복해요. 교과서는 max()를 쓰지 않고 “지금까지의 최댓값”을 직접 찾는 알고리즘을 자주 물어봐요. 부모가 파이썬을 몰라도 “첫 번째 값은 몇 번 칸이야?” 한 질문으로 핵심을 점검할 수 있어요. 결과는 모두 실행으로 확인했어요.

파이썬 ⑤ 함수이름 붙인 코드 묶음, 매개변수와 반환값

핵심 개념

  • 함수는 자주 쓰는 코드를 묶어 이름을 붙인 것: def로 정의하고 이름으로 호출해요.
  • 매개변수로 값을 받고, return으로 결과를 돌려줘요.
  • 함수로 나누면 읽기 쉽고, 고치기 쉽고, 다시 쓸 수 있어요(분해·추상화).

부모 역할 · 이렇게 도와요

  1. “이 함수는 무엇을 받아서 무엇을 돌려줘?” 한 문장 설명 요청.
  2. 레시피 비유: “라면 끓이기(물 양)”처럼 재료(매개변수)를 넣으면 결과가 나오는 것.
  3. 긴 코드를 보면 “여기를 함수로 나누면 어때?” 제안만.
def average(nums): return sum(nums) / len(nums) print(average([80, 90, 100])) # 90.0

  • 나만의 도구 함수 모음(단위 변환, 평균).

함수는 코드 묶음에 이름을 붙인 것이에요. def 이름(매개변수): 로 정의만 하면 아무 일도 안 일어나고, 이름(값)으로 호출해야 실행돼요. 호출할 때 넣은 값(인자)이 매개변수에 들어가고, return은 결과를 호출한 자리로 돌려주며 함수를 즉시 끝내요. print는 화면에 보여 줄 뿐 값을 돌려주지 않아서, return 없는 함수의 결과를 변수에 담으면 None(없음)이 들어가요. 레시피 비유가 좋아요: 재료(매개변수)를 넣으면 요리(반환값)가 나와요. 부모가 파이썬을 몰라도 “이 함수는 뭘 받아서 뭘 돌려줘?” 한 질문이면 충분해요. 결과는 실제 실행으로 확인했어요.

  2. 이해하기 — 함께 풀기

    함께 풀기

    문제: 90점 이상 A, 80점 이상 B, 나머지 C인 등급 프로그램이에요. 테스트로 버그를 찾아요.

    def grade(score):
    if score > 90:
        return "A"
    elif score >= 80:
        return "B"
    else:
        return "C"

for s in [95, 90, 85, 0, -5]:
    print(s, grade(s))
    1. 보통 값 95 → A (기대 A, 통과), 85 → B (기대 B, 통과)
    2. 경계값 90 → B (기대 A, 실패!) 90 > 90이 거짓이라서예요. >를 >=로 고쳐요.
    3. 경계값 0 → C (통과)
    4. 잘못된 값 -5 → C (점수가 음수일 수 없는데 그냥 C가 나와요) → “잘못된 점수” 처리를 추가해야 해요.
    5. 테스트 표(입력 / 기대 결과 / 실제 결과 / 통과?)를 일지에 붙이면 수행평가 과정 자료가 돼요.

영역 이해 체크리스트

AI를 “쓰는 사람”을 넘어 AI가 어떻게 배우고 어디서 틀리는지 이해하는 영역이에요. 수식보다 체험과 토론이 중심이에요.

인공지능의 이해규칙 기반 vs 학습 기반, AI가 잘하는 것과 못하는 것

핵심 개념

  • 규칙 기반: 사람이 조건을 직접 적어요(if 규칙). 학습 기반(기계학습): 데이터에서 규칙을 찾아요.
  • AI가 쓰이는 곳: 인식(이미지·음성), 추천, 번역, 생성(글·그림).
  • AI의 한계: 학습 데이터 밖의 상황, 그럴듯한 오답, 이유를 설명하기 어려움.
