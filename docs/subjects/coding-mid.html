정보 · 중학교 단원 지도

중학교에서 정보가 독립 교과로 시작돼요. 5개 영역(컴퓨팅 시스템, 데이터, 알고리즘과 프로그래밍, 인공지능, 디지털 문화)의 대표 단원을 핵심 개념과 확인 질문으로 정리했어요. 부모 역할은 가르치기가 아니라 설명시키기, 프로젝트 지원, 스크린 균형이에요. 파이썬을 몰라도 이 페이지의 질문만으로 충분히 도울 수 있어요.

이 페이지 쓰는 법

1

편성 학년 확인

정보는 중1~3 중 한두 학년에 몰아서 편성돼요. 학교알리미나 설명회 자료로 “우리 학교는 몇 학년에”를 먼저 확인해요.

2

영역 탭 고르기

학년 대신 영역별 탭이에요. 아이 교과서 목차와 짝을 지어 지금 배우는 단원만 펼쳐요.

3

확인 질문 = 대화

“엄마한테 설명해 줄래?”로 확인 질문을 던져요. 답은 ‘답 보기’에 있어요.

4

수행평가 달력

정보는 프로젝트·실습형 수행평가 비중이 커요. 학기 초 평가 계획을 받아 두세요.

2022 개정 교육과정에서 중학교 정보는 68시간 이상으로 늘었다고 안내돼요(기존 34시간). 중학교 새 교육과정은 2025년 중1부터 학년별로 적용되고, 정보를 몇 학년에 몇 시간 편성할지는 학교가 정해요(학교자율시간 활용 포함). 정보는 검정 교과서라 단원 이름·순서가 출판사마다 달라요. 텍스트 언어로 파이썬을 쓰는 교과서가 많지만 다른 언어나 블록·텍스트 병행인 경우도 있어요.

아래 단원은 성취기준 기반 대표 단원이에요. 첫째는 2031년, 둘째는 2032년에 중학생이 되니 그 사이 정책이 바뀔 수 있어요. 성취기준 원문: NCIC, 학교별 편성: 학교알리미.

🗣️

설명시키기

“이 코드 한 줄씩 읽어 줄래?” 부모는 파이썬을 몰라도 돼요. 설명하다 막히는 곳이 아이가 모르는 곳이에요.

🛠️

프로젝트 지원

주제 찾기 질문, 테스터 역할, 마감 계획 세우기 돕기. 코드를 대신 고쳐 주지 않아요.

🐞

오류 메시지 같이 읽기

빨간 글씨에 멈추는 좌절이 가장 커요. “컴퓨터가 몇 번째 줄에서 뭐라고 해?”만 같이 읽어도 절반은 해결돼요.

⚖️

스크린 균형

“만드는 스크린”도 시간 약속 안에서. 게임·영상과 섞이지 않게 장소와 시간을 나눠요(스크린타임).

🤖

AI는 도우미, 대필자 아님

코드를 AI가 통째로 써 주면 배움이 사라져요. “막힌 한 줄만 묻고, 이해한 뒤 내가 다시 쓰기”.

영역별 단원 지도

중학교 정보는 학년군(중1~3)으로 묶여 있어 학년이 아닌 영역으로 탭을 나눴어요. 대부분의 교과서가 컴퓨팅 시스템·데이터로 시작해 알고리즘과 프로그래밍에 가장 많은 시간을 쓰고, 인공지능·디지털 문화로 마무리하지만 순서는 다를 수 있어요.

컴퓨터가 “어떻게 생겼고 어떻게 서로 연결되는지”를 배우는 영역이에요. 하드웨어·소프트웨어·운영체제의 역할, 네트워크, 센서를 쓰는 피지컬 컴퓨팅이 대표 내용이에요.

컴퓨팅 기기의 구성과 동작하드웨어·소프트웨어·운영체제의 역할

핵심 개념

  • 하드웨어: 입력·출력 장치, 처리 장치(CPU), 기억 장치(주기억 메모리 = 작업대, 보조기억 저장장치 = 서랍).
  • 소프트웨어: 운영체제(기기 전체 관리, 자원 배분)와 응용 소프트웨어(앱).
  • 프로그램은 저장장치에 있다가 실행할 때 메모리로 올라와 CPU가 명령을 하나씩 처리해요.

부모 역할 · 이렇게 도와요

  1. “폰 저장공간은 넉넉한데 왜 앱을 많이 켜면 느려질까?” 질문으로 메모리와 저장장치 차이를 설명하게 해요.
  2. 집 컴퓨터 사양(설정 → 시스템 정보)을 아이가 읽어 주게 해요.
  3. “운영체제가 없으면 어떤 일이 벌어질까?” 상상 설명 듣기.
집에서 하는 활동
  • 가족 기기 사양 비교표 만들기(CPU·메모리·저장공간).
  • 작업 관리자로 어떤 앱이 메모리를 많이 쓰는지 같이 보기.
자주 틀리는 곳
  • 메모리(RAM)와 저장공간을 같은 것으로 생각해요 → 작업대(RAM)와 서랍(저장장치) 비유.
  • 운영체제를 앱 중 하나로 생각해요 → 다른 모든 앱이 그 위에서 돌아가는 “관리자”라고 구별해요.
확인 질문
  1. 전원을 끄면 내용이 사라지는 기억 장치는?
    답 보기

    주기억 장치(RAM)예요. 저장장치(SSD 등)는 전원이 꺼져도 남아요.

  2. 운영체제가 하는 일 두 가지는?
    답 보기

    예: 하드웨어 자원(CPU·메모리) 관리, 파일 관리, 사용자와 기기 연결(화면·입력).

  3. 프로그램을 실행하면 어디에서 어디로 옮겨질까?
    답 보기

    저장장치에서 주기억 장치로 올라와 CPU가 처리해요.

연결

초5 실과 컴퓨터와 소프트웨어(초등 단원 지도) → 이 단원 → 고등 정보 컴퓨팅 시스템.

네트워크와 인터넷데이터가 어떻게 오가는가

핵심 개념

  • 네트워크는 기기들이 서로 데이터를 주고받도록 연결된 것, 인터넷은 전 세계 네트워크의 네트워크예요.
  • 데이터는 작은 조각(패킷)으로 나뉘어 주소(IP)를 보고 전달되고, 도착해서 다시 합쳐져요.
  • 유선·무선(와이파이) 연결, 공유기의 역할, 공용 와이파이의 보안 위험.

부모 역할 · 이렇게 도와요

  1. “영상 통화할 때 할머니 얼굴은 어떤 길로 오는 걸까?” 설명하게 해요.
  2. 집 공유기를 같이 보며 “우리 집 네트워크 지도”를 그려 보게 해요.
  3. 카페 와이파이에서 은행 앱을 쓰지 않는 이유를 이야기해요.
집에서 하는 활동
  • 종이 패킷 놀이: 편지를 여러 조각에 번호 붙여 나눠 보내고 다시 맞추기.
  • 우리 집 네트워크 지도 그리기(공유기, 연결된 기기).
자주 틀리는 곳
  • 와이파이 = 인터넷이라고 생각해요 → 와이파이는 기기와 공유기 사이의 무선 연결일 뿐이에요.
  • 데이터가 한 덩어리로 간다고 생각해요 → 조각나서 다른 길로 가기도 한다는 걸 패킷 놀이로.
확인 질문
  1. 패킷이란?
    답 보기

    전송을 위해 작게 나눈 데이터 조각이에요. 순서 번호와 주소 정보가 붙어요.

  2. 와이파이와 인터넷의 차이는?
    답 보기

    와이파이는 공유기까지의 무선 연결 방식, 인터넷은 전 세계 네트워크의 연결이에요.

  3. 공용 와이파이에서 주의할 점은?
    답 보기

    다른 사람이 데이터를 엿볼 수 있어 로그인·결제 같은 민감한 작업은 피해요.

연결

이 단원 → 디지털 문화(정보보호) → 고등 정보 네트워크.

피지컬 컴퓨팅센서 입력 → 프로그램 → 출력 장치

핵심 개념

  • 센서(빛·온도·거리·소리) 값을 읽어 조건에 따라 LED·모터·스피커를 제어해요.
  • 센서 값은 숫자라서 기준값(임계값)을 정하는 것이 핵심이에요.
  • 입력-처리-출력 구조로 생활 문제(자동 조명, 화분 물 알림)를 해결하는 작품을 설계해요.

부모 역할 · 이렇게 도와요

  1. “우리 집에 필요한 자동 장치가 뭘까?” 주제 찾기 대화.
  2. 작품 시연 때 테스터가 되어 “이럴 때는 어떻게 돼?” 예외 상황 질문하기(너무 밝을 때, 센서를 가렸을 때).
  3. 교구 구입은 학교 수업 뒤 아이 흥미가 이어질 때만.
집에서 하는 활동
  • 생활 속 센서 기기 분석 보고서(자동문, 스마트 체중계).
  • 무료 시뮬레이터로 교육용 보드 코딩 체험.
자주 틀리는 곳
  • 기준값을 한 번 재고 정해서 환경이 바뀌면 오작동 → 여러 조건에서 값을 재어 표로 정리하고 정해요.
  • 배선·배터리 안전 무시 → 정해진 전원만, 단락 주의.
확인 질문
  1. 거리 센서로 “가까이 오면 경고음”을 만들 때 필요한 구조는?
    답 보기

    반복하며 거리 값을 읽고, 만약 거리 < 기준값이면 소리 출력.

  2. 임계값(기준값)은 어떻게 정하면 좋을까?
    답 보기

    실제 환경에서 센서 값을 여러 번 측정해 보고 정해요.

  3. 피지컬 컴퓨팅의 입력·처리·출력 예를 하나 들어 볼래?
    답 보기

    예: 토양 수분 센서(입력) → “마르면” 판단(처리) → LED·알림(출력).

연결

초6 센서와 피지컬 → 이 단원 → 고등 소프트웨어와 생활(피지컬·메이킹).

영역 이해 체크리스트

세상의 정보가 0과 1로 바뀌는 방법, 그리고 데이터를 모으고 정리하고 그래프로 보며 의미를 찾는 방법을 배워요. 수학 “자료의 정리와 해석”과 짝꿍 영역이에요.

디지털 데이터 표현수·문자·이미지·소리를 0과 1로

핵심 개념

  • 비트(0/1)와 바이트(8비트). n비트로 2ⁿ가지를 나타낼 수 있어요.
  • 문자는 약속된 코드(유니코드 등)로, 이미지는 픽셀과 색 값으로, 소리는 일정 간격으로 잰 값(표본화)으로 나타내요.
  • 압축: 데이터 크기를 줄이는 방법. 원래대로 되돌릴 수 있는 무손실, 일부 정보를 버리는 손실 압축.

부모 역할 · 이렇게 도와요

  1. “사진 한 장이 왜 몇 MB나 될까?” 해상도 × 색 정보로 설명하게 해요.
  2. 초3 이진수 카드를 꺼내 동생에게 가르쳐 보게 해요(설명시키기의 좋은 기회).
  3. 같은 사진을 다른 품질로 저장해 크기·화질 비교하기.
집에서 하는 활동
  • 파일 크기 탐정: 글·사진·음악·영상 파일 크기 비교표.
  • 반복 글자 압축 놀이: “AAAABBB” → “A4B3”.
자주 틀리는 곳
  • 비트 수를 1 늘리면 표현 개수가 1 늘어난다고 생각해요 → 2배가 된다는 걸 표로 확인.
  • 손실 압축도 원본으로 되돌릴 수 있다고 생각해요 → 버린 정보는 복구 못 해요.
확인 질문
  1. 3비트로 나타낼 수 있는 경우의 수는?
    답 보기

    2³ = 8가지.

  2. 이미지 해상도를 가로·세로 2배로 늘리면 픽셀 수는?
    답 보기

    4배가 돼요.

  3. 손실 압축과 무손실 압축의 차이는?
    답 보기

    무손실은 원래대로 복원 가능, 손실은 일부 정보를 버려 더 작지만 복원이 안 돼요.

연결

초3 이진수·픽셀 → 이 단원 → 고등 정보 데이터 표현. 수학 중2 거듭제곱과 연결.

데이터 수집·관리·분석표로 정리하고 그래프로 의미 찾기

핵심 개념

  • 문제 해결에 필요한 데이터를 정하고 모으기(설문, 측정, 공공데이터).
  • 표(행 = 한 사례, 열 = 속성)로 구조화하고, 빠진 값·잘못된 값을 정리해요.
  • 스프레드시트로 정렬·필터·합계·평균, 알맞은 그래프(막대·꺾은선·원)로 시각화하고 해석해요.

부모 역할 · 이렇게 도와요

  1. 진짜 가족 데이터를 줘요: 한 달 전기요금, 가족 수면 시간, 용돈 기록.
  2. “이 그래프로 무엇을 말하고 싶어?” 한 문장 결론을 먼저 말하게 해요.
  3. “다른 그래프로 그리면 더 잘 보일까?” 선택 이유를 묻기.
집에서 하는 활동
  • 가족 수면·스크린 시간 2주 기록 → 그래프 → 가족 회의 자료.
  • 공공데이터(기온, 미세먼지)로 우리 동네 그래프 만들기.
자주 틀리는 곳
  • 한 칸에 여러 정보를 넣어요(“7시간, 늦게 잠”) → 한 칸 한 값 원칙.
  • 변화를 원그래프로 그려요 → 시간에 따른 변화는 꺾은선, 비율은 원그래프.
  • 상관을 원인으로 해석해요 → “같이 늘었다”와 “때문에 늘었다”를 구별하게 해요.
확인 질문
  1. 한 달 동안 기온 변화를 보여 주기 좋은 그래프는?
    답 보기

    꺾은선그래프예요.

  2. 표에서 행과 열은 각각 무엇을 나타낼까?
    답 보기

    보통 행은 한 사례(한 사람, 하루), 열은 속성(이름, 기온)이에요.

  3. 아이스크림 판매와 물놀이 사고가 함께 늘면 아이스크림이 사고 원인일까?
    답 보기

    아니에요. 둘 다 더운 날씨 때문에 함께 늘었을 수 있어요(상관 ≠ 인과).

연결

수학 중1 자료의 정리와 해석(수학 중학교) ↔ 이 단원 → 인공지능(데이터로 학습) → 고등 데이터 과학.

영역 이해 체크리스트

중학교 정보에서 가장 많은 시간을 쓰는 영역이에요. 알고리즘을 설계하고, 블록에서 텍스트 언어(주로 파이썬)로 넘어가 변수·입출력 → 조건 → 반복 → 리스트 → 함수 → 프로젝트 순서로 배워요. 부모는 코드를 몰라도 “설명해 줄래?”와 “오류 메시지 같이 읽기”로 충분해요.

아래 코드 예시는 부모가 아이 설명을 들을 때 “대충 이런 모양”을 알아보기 위한 것이에요. 외우거나 가르칠 필요는 없어요.

문제 분석과 알고리즘 설계순서도·의사코드, 탐색과 정렬

핵심 개념

  • 문제 분석: 입력(주어진 것)·출력(구할 것)·조건을 정리해요.
  • 알고리즘 표현: 순서도, 의사코드(우리말로 쓴 코드 같은 글).
  • 대표 알고리즘: 순차 탐색, (정렬된 자료의) 이진 탐색, 간단한 정렬. 같은 문제도 알고리즘에 따라 단계 수가 달라요.

부모 역할 · 이렇게 도와요

  1. “코딩 전에 종이에 먼저 써 봤어?” 습관 질문.
  2. 업다운 게임을 다시 하며 “이진 탐색을 엄마한테 설명해 줘”.
  3. 생활 문제(가족 여행 최단 경로, 장보기 순서)를 순서도로 그려 달라고 부탁해요.
집에서 하는 활동
  • 카드 정렬 대결: 서로 다른 방법으로 정렬하며 비교 횟수 세기.
  • 의사코드로 “아침 루틴” 쓰기.
자주 틀리는 곳
  • 바로 코딩부터 해서 헤매요 → 입력·출력·조건 세 줄 정리부터.
  • 정렬 안 된 자료에 이진 탐색을 쓰려 해요 → 이진 탐색은 정렬이 전제라는 걸 확인.
확인 질문
  1. 1~1000 사이 숫자를 이진 탐색으로 찾으면 최대 몇 번쯤?
    답 보기

    약 10번(2¹⁰ = 1024).

  2. 의사코드란?
    답 보기

    특정 언어 문법 없이 알고리즘을 사람의 말로 코드처럼 적은 것이에요.

  3. 순서도에서 반복은 어떻게 나타날까?
    답 보기

    판단(마름모)에서 앞 단계로 되돌아가는 화살표로 나타나요.

연결

초4 정렬·초5 절차적 문제 해결 → 이 단원 → 파이썬 단원들 → 고등 정보 알고리즘 효율.

파이썬 ① 변수·자료형·입출력블록에서 글자로, 첫 프로그램

핵심 개념

  • 변수에 값을 대입해요: score = 0. 여기서 =는 “같다”가 아니라 “오른쪽 값을 왼쪽 이름에 저장”이에요.
  • 자료형: 정수, 실수, 문자열("안녕"), 논리값(True/False). input()으로 받은 값은 문자열이라 계산하려면 int()로 바꿔요.
  • 연산자: 산술(+ − * / // %), 비교(== != < >), 논리(and or not).

부모 역할 · 이렇게 도와요

  1. 아이가 첫 프로그램(이름 묻고 인사하기)을 보여 주면 “한 줄씩 읽어 줄래?”
  2. “=랑 ==는 뭐가 달라?” 질문 하나면 핵심을 확인할 수 있어요.
  3. 오류가 나면 빨간 글씨의 마지막 줄과 줄 번호를 같이 읽어요.
name = input("이름은? ") age = int(input("나이는? ")) print(name, "님, 내년엔", age + 1, "살!")
집에서 하는 활동
  • 용돈 계산기, 섭씨↔화씨 변환기 만들기.
  • 가족에게 “이름 묻고 인사하는 프로그램” 시연.
자주 틀리는 곳
  • =를 수학의 등호로 읽어 x = x + 1이 이상하다고 해요 → “오른쪽을 계산해서 왼쪽에 넣는다”로 읽기.
  • 변수를 값이 쌓이는 상자로 생각해요 → 새로 대입하면 이전 값은 사라져요. 이름표 비유로 다시 설명.
  • input() 값을 바로 더해 "3"+"4" = "34"가 나와요 → 문자열과 정수의 차이를 확인.
확인 질문
  1. x = 3 다음 x = x + 2를 실행하면 x는?
    답 보기

    5예요.

  2. "3" + "4"의 결과는?
    답 보기

    "34"(문자열 이어 붙이기). 정수로 바꾸면 7.

  3. 7 // 2와 7 % 2의 값은?
    답 보기

    3(몫)과 1(나머지).

연결

초6 변수와 데이터 → 이 단원 → 조건문. 수학 중1 문자와 식(수학 중학교)에 익숙하면 훨씬 쉬워요.

파이썬 ② 조건문if · elif · else, 들여쓰기

핵심 개념

  • if 조건: 아래 들여쓴 줄은 조건이 참일 때만 실행돼요. elif는 “아니면 만약”, else는 “나머지 모두”.
  • 파이썬은 들여쓰기로 “어디까지가 이 조건 안인지”를 구별해요.
  • 조건은 위에서부터 검사하고, 참인 첫 번째만 실행해요.

부모 역할 · 이렇게 도와요

  1. “점수에 따라 등급을 매기는 규칙을 먼저 말로 해 줄래?” → 그다음 코드.
  2. 테스터 역할: 경계값(정확히 90점, 0점, 음수)을 넣어 보라고 제안해요.
  3. 들여쓰기 오류는 줄 맞추기만 보면 된다고 안심시켜요.
if score >= 90: print("A") elif score >= 80: print("B") else: print("다음엔 더 잘할 수 있어!")
집에서 하는 활동
  • 날씨·기온을 입력하면 옷차림 추천하는 프로그램.
  • 가위바위보 게임(컴퓨터 무작위 선택 + 승패 판정).
자주 틀리는 곳
  • 조건 순서를 거꾸로 써서(80 이상을 먼저) 95점이 B가 돼요 → 위에서부터 검사한다는 것을 손으로 따라가 보기.
  • if와 반복을 혼동해 “조건이 맞는 동안 계속”이라고 생각해요 → if는 한 번 검사, 계속 검사는 while.
  • =와 == 혼동.
확인 질문
  1. 위 예시에서 score가 85이면 출력은?
    답 보기

    B.

  2. if와 elif를 여러 개 쓸 때 조건 순서가 중요한 까닭은?
    답 보기

    위에서부터 검사해 참인 첫 번째만 실행하기 때문이에요.

  3. 짝수인지 판단하는 조건식은?
    답 보기

    n % 2 == 0.

연결

초5 선택과 이벤트 → 이 단원 → 반복문.

파이썬 ③ 반복문for · range · while, 무한 반복 주의

핵심 개념

  • for i in range(5):는 i가 0, 1, 2, 3, 4일 때 5번 반복(횟수가 정해진 반복).
  • while 조건:은 조건이 참인 동안 반복(끝나는 시점이 조건에 달린 반복). 조건이 영원히 참이면 무한 반복.
  • 누적 패턴: total = 0으로 시작해 반복마다 더하기.

부모 역할 · 이렇게 도와요

  1. “range(1, 11)은 몇부터 몇까지야?” 한 질문으로 가장 흔한 실수를 점검.
  2. 프로그램이 멈추지 않으면 당황하지 말고 중지(Ctrl+C 등) 후 “while 조건이 언제 거짓이 돼?” 묻기.
  3. 구구단 출력처럼 결과가 눈에 보이는 과제를 제안해요.
total = 0 for i in range(1, 11): total = total + i print(total) # 55
집에서 하는 활동
  • 구구단 전체 출력, 1부터 100까지 짝수 합.
  • 숫자 맞히기 게임(while로 맞힐 때까지 반복).
자주 틀리는 곳
  • range 끝 값이 포함된다고 생각해요 → range(1, 11)은 10까지.
  • while 안에서 조건 변수를 바꾸지 않아 무한 반복 → “반복할 때마다 무엇이 바뀌어 끝나게 돼?”
  • 누적 변수를 반복 안에서 0으로 초기화해 매번 리셋 → 초기화는 반복 밖에서.
확인 질문
  1. range(3)이 만드는 수는?
    답 보기

    0, 1, 2.

  2. for와 while은 언제 각각 쓸까?
    답 보기

    반복 횟수가 정해져 있으면 for, 조건이 만족될 때까지면 while.

  3. 위 예시에서 total = 0을 반복 안에 넣으면?
    답 보기

    매번 0으로 초기화돼 마지막 값 10만 남아요.

연결

초5 순차와 반복 → 이 단원 → 리스트(반복과 짝꿍).

파이썬 ④ 리스트여러 값을 한 이름으로, 인덱스와 반복

핵심 개념

  • 리스트는 여러 값을 순서대로 담아요: scores = [80, 95, 70].
  • 인덱스는 0부터 시작: scores[0]은 80. len()으로 개수, append()로 추가.
  • for s in scores:로 모든 값을 차례로 처리해요(합계·최댓값·개수 세기).

부모 역할 · 이렇게 도와요

  1. 가족 데이터(가족 키, 이번 주 걸음 수)를 리스트로 만들어 평균·최댓값을 구해 달라고 부탁해요.
  2. “첫 번째 값은 몇 번 칸이야?” 0부터 세는 것만 확인.
  3. 결과를 가족 단톡방에 공유하는 즐거움 주기.
steps = [5200, 8100, 6400, 9900] print(max(steps), sum(steps) / len(steps))
집에서 하는 활동
  • 가족 걸음 수 통계, 단어장 퀴즈(리스트에서 무작위 출제).
  • 할 일 목록 프로그램(추가·삭제·보기).
자주 틀리는 곳
  • 인덱스를 1부터 세서 마지막 칸에서 오류(IndexError) → 0부터, 마지막은 len−1.
  • 변수와 리스트를 구별 못 해요 → 변수는 값 하나, 리스트는 번호 붙은 칸 여러 개.
확인 질문
  1. a = [3, 6, 9]에서 a[2]는?
    답 보기

    9.

  2. 리스트 길이가 5면 마지막 인덱스는?
    답 보기

    4.

  3. 리스트의 모든 값을 더하는 방법 두 가지는?
    답 보기

    sum(a), 또는 누적 변수와 for 반복.

연결

반복문·데이터 영역 → 이 단원 → 함수 → 고등 정보 2차원 리스트·데이터 분석.

파이썬 ⑤ 함수이름 붙인 코드 묶음, 매개변수와 반환값

핵심 개념

  • 함수는 자주 쓰는 코드를 묶어 이름을 붙인 것: def로 정의하고 이름으로 호출해요.
  • 매개변수로 값을 받고, return으로 결과를 돌려줘요.
  • 함수로 나누면 읽기 쉽고, 고치기 쉽고, 다시 쓸 수 있어요(분해·추상화).

부모 역할 · 이렇게 도와요

  1. “이 함수는 무엇을 받아서 무엇을 돌려줘?” 한 문장 설명 요청.
  2. 레시피 비유: “라면 끓이기(물 양)”처럼 재료(매개변수)를 넣으면 결과가 나오는 것.
  3. 긴 코드를 보면 “여기를 함수로 나누면 어때?” 제안만.
def average(nums): return sum(nums) / len(nums) print(average([80, 90, 100])) # 90.0
집에서 하는 활동
  • 게임 코드 속 반복되는 부분을 함수로 정리하기.
  • 나만의 도구 함수 모음(단위 변환, 평균).
자주 틀리는 곳
  • print와 return을 같은 것으로 생각해요 → print는 화면에 보여 주기, return은 값을 돌려줘 다른 계산에 쓸 수 있게.
  • 함수를 정의만 하고 호출하지 않아 아무 일도 안 일어나요.
확인 질문
  1. 함수를 쓰면 좋은 점 두 가지는?
    답 보기

    같은 코드를 반복해 쓰지 않아도 되고, 읽고 고치기 쉬워요.

  2. print와 return의 차이는?
    답 보기

    print는 화면 출력, return은 호출한 곳에 값을 돌려줘요.

  3. def만 쓰고 아무 일도 안 일어나는 까닭은?
    답 보기

    함수를 호출하지 않았기 때문이에요.

연결

리스트 → 이 단원 → 프로젝트 → 고등 정보 모듈화.

프로그래밍 프로젝트생활 문제를 코드로 해결하고 발표

핵심 개념

  • 문제 발견 → 분석(입력·출력) → 설계(알고리즘·함수 나누기) → 구현 → 테스트·디버깅 → 공유.
  • 테스트: 보통 값, 경계값, 잘못된 값을 넣어 보기.
  • 협업 프로젝트는 역할 나누기와 코드 합치기가 핵심이에요.

부모 역할 · 이렇게 도와요

  1. 주제 찾기 질문: “요즘 불편한 게 뭐야? 반 친구들은?”
  2. 마감 거꾸로 계획표를 함께: 발표일 → 테스트 주 → 구현 주 → 설계 주.
  3. 가족이 테스터·청중이 되어 주기. “여기 이상한 값 넣으면 어떻게 돼?”
  4. 코드는 대신 고치지 않기. 수행평가라면 AI 사용 규칙도 학교 기준에 맞는지 확인.
집에서 하는 활동
  • 반 친구 퀴즈 앱, 급식 메뉴 추천기, 공부 타이머.
  • 프로젝트 일지: 날짜 / 한 일 / 만난 버그 / 해결.
자주 틀리는 곳
  • 마감 전날 몰아 하다 디버깅 시간이 없어요 → 계획표의 절반을 테스트·수정에.
  • 디버깅이 길어지면 “나는 코딩이 안 맞아”로 결론 → 프로 개발자도 시간의 상당 부분을 디버깅에 쓴다고 알려 주고, 해결한 버그를 기록해 성장으로 보여 줘요.
확인 질문

영역 이해 체크리스트

AI를 “쓰는 사람”을 넘어 AI가 어떻게 배우고 어디서 틀리는지 이해하는 영역이에요. 수식보다 체험과 토론이 중심이에요.

인공지능의 이해규칙 기반 vs 학습 기반, AI가 잘하는 것과 못하는 것

핵심 개념

  • 규칙 기반: 사람이 조건을 직접 적어요(if 규칙). 학습 기반(기계학습): 데이터에서 규칙을 찾아요.
  • AI가 쓰이는 곳: 인식(이미지·음성), 추천, 번역, 생성(글·그림).
  • AI의 한계: 학습 데이터 밖의 상황, 그럴듯한 오답, 이유를 설명하기 어려움.

부모 역할 · 이렇게 도와요

  1. “영상 추천은 어떻게 내 취향을 알까?” 설명해 달라고 하기.
  2. 스팸 필터를 규칙으로 만들면 어떤 문제가 생길지 토론.
  3. 생성형 AI가 틀린 답을 낸 경험을 서로 이야기하기.
집에서 하는 활동
  • 우리 집 AI 찾기: 스마트 스피커, 사진 앱 얼굴 분류, 번역기.
  • 추천 알고리즘 실험: 새 계정(또는 기록 삭제)으로 추천이 어떻게 바뀌는지 관찰.
자주 틀리는 곳
  • AI는 항상 정확하고 중립적이다 → 데이터와 설계에 따라 틀리고 치우칠 수 있어요.
  • 모든 자동화 = AI라고 생각해요 → 단순 규칙(if) 프로그램과 학습하는 AI를 구별해요.
확인 질문
  1. 규칙 기반과 기계학습의 차이는?
    답 보기

    규칙 기반은 사람이 규칙을 적고, 기계학습은 데이터에서 규칙을 찾아요.

  2. 생성형 AI 답을 그대로 믿으면 안 되는 까닭은?
    답 보기

    사실이 아닌 내용을 그럴듯하게 만들어 낼 수 있기 때문이에요.

  3. AI가 쓰이는 예 두 가지는?
    답 보기

    예: 음성 인식, 번역, 추천, 이미지 분류.

기계학습 체험과 AI의 영향데이터로 학습시키기, 편향과 책임

핵심 개념

  • 지도학습: 정답(레이블)이 붙은 데이터로 학습 → 새 데이터를 분류·예측.
  • 학습 데이터와 평가(테스트) 데이터를 나눠 성능을 확인해요.
  • 데이터 편향은 결과 편향으로 이어져요. AI 결정의 책임은 만든 사람과 쓰는 사람에게 있어요.

부모 역할 · 이렇게 도와요

  1. 아이가 만든 분류 모델을 시연하면 “일부러 틀리게 만들어 볼 수 있어?”라고 물어요.
  2. 뉴스 속 AI 채용·얼굴 인식 편향 사례를 함께 읽고 의견 나누기.
  3. “AI가 잘못 판단하면 누구 책임일까?” 정답 없는 대화.
집에서 하는 활동
  • 교육용 기계학습 도구로 재활용품 분류 모델 만들기.
  • 데이터 양·다양성을 바꿔 정확도 비교 실험 기록.
자주 틀리는 곳
  • 학습에 쓴 데이터로 평가해 정확도가 높다고 착각 → 새 데이터로 확인해야 해요.
  • 데이터가 많으면 편향이 없다고 생각 → 양보다 고르게 대표하는지가 중요.
확인 질문

    답 보기

    처음 보는 데이터에서도 잘 맞히는지 공정하게 확인하려고요.

  2. 한 피부색 사진만으로 학습한 얼굴 인식 AI의 문제는?
    답 보기

    다른 피부색의 얼굴을 잘 인식하지 못하는 편향이 생길 수 있어요.

  3. 지도학습에서 “레이블”이란?
    답 보기

    데이터에 붙인 정답(예: 이 사진은 “고양이”).
